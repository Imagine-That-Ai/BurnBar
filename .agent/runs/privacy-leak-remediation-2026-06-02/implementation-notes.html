Decisions Outside The Spec

  • Gateway = TRUE E2E re-architecture (Alberto ratified 2026-06-03). Recon proved Hermes Gateway is a store-and-forward bridge to a keyless third-party agent (tools/hermes-platform-burnbar/adapter.py); the server never reads bodies for logic, but the far end holds no vault key. Sealing with the vault key was rejected (would hand the master key to arbitrary external processes). Alberto chose to make it genuinely E2E by retiring the open bearer-token adapter and routing gateway traffic through the already-E2E first-party relay (HermesRelayCrypto/HermesRelayKeyStore, hermes_relay_requests). This is a product re-architecture — being scoped/designed separately (see Next Goal Candidates) so it is done right, not rushed alongside the bounded leak fixes. This corrects my earlier adversarial report which called the gateway a "critical leak to seal."
  • usage/budget project text = SEAL E2E (Alberto ratified). Server never reads projectName/label (budget enforcement is 100% client-side; rollups key on provider/account/model/device). Add sealedProjectName/sealedLabel via CloudVaultCrypto.sealText on Mac/iOS/Android + optional projectKeyHash (HMAC trapdoor) for grouping; legacy plaintext fallback during migration; flip usage_spend registry tier away from server-readable for project text. Makes session_logs' "project text device-only" claim true app-wide.
  • project_memory = seal + opaque deterministic doc id. The name is already inside the sealed blob; plaintext projectDisplayName + name-derived doc-id slug are redundant leaks. New Swift primitive CloudVaultCrypto.projectMemoryDocID(forSlug:keyData:) = "pm_"+HMAC(slug).prefix16.hex (deterministic ⇒ upsert idempotent; opaque ⇒ server learns nothing; passes requiredIdentifier unchanged). No product fork.
  • Crypto contract is locked: reuse existing platform CloudVaultCrypto only (byte-identical AES-256-GCM envelopes across Swift/Kotlin/TS/web/Node). Android has no sealBlob — but our Android work is read + short-text only, so no gap. Full contract in evidence/recon-crypto-primitives.md.
  • Execution model: 5 parallel implementation streams with DISJOINT file ownership (TS / Swift / Kotlin / rules+tests / honesty+tooling), each following locked field contracts + its evidence/recon-*.md brief. Agents EDIT only; all builds/tests/verification run centrally in the integration phase (avoids build races, keeps verification coherent).
