Decisions Outside The Spec

  • macOS-14 fix playbook. Mutex (Synchronization) is macOS 15+ — unavailable. But OSAllocatedUnfairLock is macOS 13+ and is Sendable; it's the pre-Mutex box that keeps a synchronous API (no actor ripple). The old Locked<T> comment claiming "macOS 14 precludes OSAllocatedUnfairLock" was wrong (confused with Mutex) — rebuilt Locked<T> on it → plain Sendable.
  • NSLock IS Sendable; FileManager is NOT. Classes whose only "extra" is a lock guarding an external resource can drop @unchecked outright. ~6 types are @unchecked solely for a stored FileManager — legit keep-audited until Foundation annotates it.
  • Counter accuracy fix. The budget counter matched // AUDIT(@unchecked Sendable) comment lines as annotations (13 phantom counts). Fixed to count only real conformance annotations, so writing a justification no longer inflates the budget. Real start was 161, not 174.
  • Swift 6 mode deferred. Flip a target only once it hits zero @unchecked (plan rule). Core/Daemon still hold audited exceptions, so no flip yet — the genuine-Sendable work is the prerequisite.
  • Audited exceptions kept, not papered. 15 in Core/Daemon carry in-code AUDIT(@unchecked Sendable) justifications (FFI handles, raw SQLite pointers, Process, CoreHID, FileManager). These count toward the budget today; reaching 0 requires resolving them (boundary type / actor / Foundation annotation) or moving them to a rationale allowlist — an open design question flagged in GOAL.md.

Changes And Tradeoffs

  • Tranche 1 boxed mutable state with Locked/OSAllocatedUnfairLock rather than converting to actor where callers are synchronous — preserves sync APIs, avoids an await ripple across the codebase.
  • Vector-index readers made real-Sendable (boxed load-once state); writers kept audited (single-threaded builders — boxing the HNSW graph builder's hot path was judged risky for no real safety gain).
  • OBBSignalSessionCipherTransport left @unchecked with a flag to actor-isolate in a dedicated PR + concurrency tests — drive-by actor conversion of E2EE ratchet code is too risky without tests.
