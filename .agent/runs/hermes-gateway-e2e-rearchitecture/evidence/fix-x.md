## CHANGELOG

### `functions/src/hermesGateway.ts`
- **Added `HERMES_GATEWAY_RELAY_KEY_VERSION = 1`** — single supported relay key version constant, used by both the write- and read-side validators. (supports findings 3 & 4)
- **`requireGatewayRelayEnvelope`** — replaced the permissive `1..100` `relayKeyVersion` range with an exact `=== HERMES_GATEWAY_RELAY_KEY_VERSION` (i.e. `1`) check. A forged/future version (v2, 101, …) is now rejected. **Closes finding 4 (KEY-VERSION CLAMP, write side).**
- **`sanitizeGatewayRelayEnvelope`** — rewrote the lax read-side check (previously accepted any non-empty strings and any numeric key version) to apply the SAME semantics as the write validator: `relayEncryption` must equal the algorithm constant, `relayKeyVersion` must equal `1`, and `payloadCiphertext`/`wrappedKey` must be base64 within the size caps. A malformed/forged/backfilled stored envelope now returns `undefined` (treated as unreadable). **Closes finding 3 (SANITIZE STRICT).** This also tightens `isHermesGatewayAttachmentManifestDoc`, which delegates manifest-envelope validation here.
- **`serializeHermesGatewayEvent`** — now computes `isSealedDoc = (valid relayEnvelope present) || schemaVersion >= 2` and UNCONDITIONALLY omits plaintext `text`/`senderDisplayName`/`threadId` for any sealed doc, even when those siblings are present on a backfilled/admin/corrupt doc. Legacy plaintext is emitted ONLY for an unsealed `schemaVersion < 2` doc. A schema-2 doc whose envelope is corrupt serializes to `undefined` (no malformed-envelope pass-through, no plaintext leak). **Closes finding 2 (SERIALIZE STRIP-SIBLINGS).**

### `functions/src/callables/hermesGateway.ts`
- **Imported `HERMES_GATEWAY_RELAY_KEY_VERSION`.**
- **`parseRelayPublicKey`** — clamped the published relay-pubkey `keyVersion` from `1..100` to exactly `HERMES_GATEWAY_RELAY_KEY_VERSION` (default and only accepted value `1`) on every advertise surface (device/start, /runtime, approve). **Closes finding 4 (KEY-VERSION CLAMP, pubkey advertise path).**
- **`handleRuntimeStatus`** — made the pinned `agentRelayPublicKey` IMMUTABLE (trust-on-first-use). The relay-key fields are written ONLY on first pairing (no key pinned yet). If a key is already pinned and an incoming `/runtime` request advertises a DIFFERENT key, it is dropped (not written) and a `hermes_gateway.relay_key_change_rejected` security event is logged; a re-publish of the same key is a no-op. `relayCapable` derivation updated to count the pinned-or-just-pinned agent key. This blocks any bearer-token holder (incl. the server) from swapping the relay key to MITM the channel. **Closes finding 1 (KEY IMMUTABILITY).** (The phone key has no post-pairing write path, so it is already immutable; `approveHermesGatewayDeviceGrant` remains the sole pinning site, writing a fresh client doc with `merge:false`.)
- **`enqueueHermesGatewayEvent` (model_switch branch)** — on a relay-capable target, a `model_switch` now REQUIRES the `relayEnvelope` (the sealed "/model …" command body) and is forwarded opaquely; the server-side plaintext `clientAdvertisesModel` catalog gate is DROPPED for relay-capable clients (the agent validates against its own catalog after opening the sealed command). The cleartext `modelId` still rides alongside for routing/optimistic-pending; no plaintext command body is stored. The legacy plaintext-catalog guard is retained ONLY for non-relay-capable clients within the (now-closed) plaintext grace window, keeping pre-E2E model_switch working. **Closes finding 5 (MODEL_SWITCH SEALED).**
