Decisions Outside The Spec

  • Shim sources are TypeScript, not JS. Plan says "edit tools/openburnbar-mcp-remote/lib/embed.js", but lib/ is gitignored compiled output (tsc, src→lib). Real source is src/*.ts. Decision: write all shim pieces (embed.ts, knowledge.ts, memoryHook.ts) as TypeScript in src/. (PRD-vs-repo mismatch; followed repo per escape hatch.)
  • Generalized buildDesired via an options arg ({sourceLabel, sourceKind, sourceSlug}) instead of forking the function, so the maintainer wiki sync and member Pensieve ingestion share one chunker. Defaults reproduce the wiki output exactly; member tags are added only when provided.
  • planActions gained an idField param (default "memory_id") so the same diff engine threads memory_id for the wiki mem0 mirror and vectorId for Pensieve. Default keeps wiki behavior identical.
  • Golden test placed at scripts/lib/verbatim-chunker.test.mjs (no root package.json / no prior scripts/*.test); runs via node --test, wired into fast-feedback.yml as the chunker-parity job.
  • P2 cloak = product of 24 Householder reflections, not a full random matrix (no linalg dep) and not a signed permutation (which a test proves leaks the coordinate-magnitude multiset). Exactly orthogonal → cosine/ranking preserved to FP precision; mixes every coordinate. Seed = HKDF(vaultKey, "Pensieve-Cloak" salt, info=modelVersion).
  • P2 embedder lazy-loaded, NOT a package dependency. The shim is deliberately "dependencies": {}. Pulling onnxruntime-node (native binaries) into its lockfile is a supply-chain cost for every user, most of whom won't use Pensieve. Chose lazy import(variableSpecifier) from the user's env (tries @huggingface/transformers then @xenova/transformers), with an actionable install error. Keeps tsc build dep-free; Pensieve embedding runtime is opt-in.
  • P2 ships a createDeterministicHashingEmbedder tagged modelVersion: "hashing-bow-v1" for offline/CI tests of the encrypt→cloak→commit→search plumbing. The version-match guard quarantines it from real bge vectors, so it can never poison production recall.
  • ★ ARCHITECTURE PIVOT (P3/P4): Firestore native vector search, NOT Cloud SQL pgvector. Grounding revealed the hosted-MCP already does per-uid retrieval over users/{uid}/… Firestore subcollections, and Firestore now supports findNearest + FieldValue.vector (384-dim COSINE). The plan's residual-open decision #1 explicitly leaves the vector engine open (pgvector = default only). Firestore is strictly better here: (1) eliminates the Cloud SQL provisioning [blocked] item entirely; (2) isolation reuses the proven owner-only firestore.rules + users/{uid}/ namespacing (no namespace-bug risk); (3) commitKnowledgeBatch writes ONE store (Firestore) not two (no cross-service DB sharing); (4) the vector index is declarative in firestore.indexes.json — deployable, not external infra. pgvector kept as a documented future scale lever in the runbook. Vectors live at users/{uid}/cloud_search_knowledge/{vectorId}; ciphertext stored INLINE (per plan intent + encryptedSearch precedent), no Cloud Storage coupling.
  • Server honors only plaintext filters (sourceKind, sourceSlug, modelVersion). sourcePath/section/category are in the SEALED metadata (encrypted) → the server cannot filter on them; the shim applies those client-side after decrypt. The tool schema still accepts them (forward-compat + client post-filter).
  • Pensieve gates on Cloud Pro (assertActiveBurnBarCloudProEntitlement, proMax-strict), not the permissive assertActiveBurnBarProEntitlement — matches the plan ("$24.99 Cloud Pro + only"). Ultra (P8) mirrors proMax via appStoreEntitlementTarget so it inherits the gate; only the limit lookup branches on burnbar_ultra.
