## 1. Executive Summary

Twenty-four hours after a diligence report that said "the code would pass diligence; the operating process would not," the team shipped a remediation sprint (PRs #298–#303, #307) that is **overwhelmingly real at the artifact level and damning at the process level — simultaneously.**

The real part: LB-3 (Firestore rules/indexes CI deploy) is fully closed with a green end-to-end production run today, including an API-level hash drift check this review independently reproduced. GCP uptime checks now exist for all four user-facing surfaces — verified live via `gcloud`, not just in code. Hosting deploys run a genuine post-deploy smoke that caught a real failure today and auto-filed an issue within 3 minutes. The nightly executed real tests for the first time in its life (protoc fixed; ~80 minutes of passing Swift suites; DAST green). The Stripe webhook fix is layered, tested, and enforced on every PR. The rollup loop fix (pagination + circuit breaker) is well-typed and tested. This is not cosmetic remediation.

The damning part, with CI receipts: at 11:35 UTC today, the un-bypassed diff-coverage gate measured PR #303's own privileged-input files at **3.2% line coverage against an 80% threshold** (run 27342067457: installer 0/136 lines, XPC client 0/47, keyboard engine 0/202). Six minutes later, commit `51485cdd7` added presence-based carve-outs for **exactly those files**; the next run passed on `method: test_file_presence`; the PR solo-merged 48 minutes later with zero human review under a REVIEW_REQUIRED decision. The same morning's commits dropped the only Kotlin/TS diff-coverage from CI — which was load-bearing for the same PR's mergeability. The team's first observable response to "your coverage gate is theater" was to widen the theater, aimed at the most dangerous surface in the product.

Two new discoveries materially change the launch picture. First, **the alerting plane has never been able to reach a human**: every one of the 16 GCP alert policies — including the 9 yesterday's report credited as "channel-backed" — notifies a single email channel, `support@openburnbar.app`, and `openburnbar.app` is **NXDOMAIN** (unregistered; verified against 8.8.8.8 and 1.1.1.1). It is also the public support contact on the website and the App Store review contact default. Second, **the production deploy plane is wedged**: today's v1.0.2 functions deploy failed on the legal release preflight (`requires_counsel_review` — a deliberate hold) *and* a CI bug (deploy-production.yml never checks out the `Vendor/libsignal` submodule, so the provenance gate fails on a missing LICENSE even after counsel clears). Production functions are pinned at June 3 — meaning the merged Stripe and rollup fixes **are not live**; the LB-5 exploit works against the production endpoint today.

The dirty working tree (the second-iteration P0-6 rework) fixes the two named defects but introduces a confirmed new one: the privileged-input transport moved from a launchd Mach service to a predictable, squattable `/tmp` Unix socket with **no client-side server authentication**, on the exact path that carries the plaintext macOS login password. And HEAD's committed socket lane shipped with a wrong `LOCAL_PEERTOKEN` constant (0x102 vs the SDK's 0x006) that makes its peer auth fail closed — proof the merged remediation was never once exercised on a live socket.

One-sentence verdict: **the artifacts improved a full grade in 24 hours; the integrity of the process that produces them got measurably worse, and both halves now have receipts.**

## 7. Diligence Risks

1. **Process-integrity evidence is now discoverable in minutes** — the coverage-gate sequence, the zero-review remediation merges, and the cleared-then-reverted F5 gate are all in CI logs and git history. These reframe "configured controls" discount-rates across the whole repo. The mitigation is a written, followed solo-operator policy (when solo-merge is acceptable, what compensating checks apply) plus visible adherence — not deletion of history.
2. **Bus factor 1, now with a sharper edge**: the only copy of the C-4 agent command-guard hardening — a claimed security control — is an unpushed commit on the founder's laptop, which is also the runtime the founder's machine executes. Uptime/alert policies were applied from the laptop outside CI provenance.
3. **The launch is legally gated and operationally entangled** — counsel review (in flight, sensible) blocks functions deploys, DMG releases, *and* keeps the health synthetic red. Expect a diligence question: "what's your hotfix path during the hold?" Today the honest answer is "bypass the preflight from a laptop."
4. **E2EE auditability** unchanged: runtime ships as .pyc, provenance verifier not in PR CI, attestation/gate commit split. Custom Double Ratchet still in production with libsignal "wired in, not activated."
5. **Single prod environment, GCP_SA_KEY, laptop Cloud Run deploys, console/functions skew** — all unchanged; the skew now actively breaks the new health gates.
6. **Cost curve** unchanged: zero TTL anywhere (verified: `gcloud firestore fields ttls list` → 0 items), no-op client purge, plus a new unbounded `stripe_webhook_events` collection.
7. **QA lane green-washing**: `qa.yml` pipes ~15 production secrets into a third-party CLI installed via `curl | sh`, with `continue-on-error: true` — concludes "success" regardless of outcome. Both a false-confidence and a supply-chain exposure.
8. **Five-day fuse**: GitHub forces Node 24 on actions June 16; every workflow shares the pinned checkout/setup-node SHAs that warned in today's logs.
