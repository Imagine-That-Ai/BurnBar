## Goal

Finish the memory program end to end: close the sync correctness holes left by the blind-backup PR (#2508), make memory visible and trustworthy in the app, widen capture without weakening honesty guarantees, add team/org memory, and bring Linux and operators along. Twenty items, five phases (A–E), sequenced so each phase is shippable on its own.

## Success Criteria

- A memory edited on two devices offline converges to one body with no resurrection of forgotten rows and no order dependence.
- Every user-visible memory can answer: its revisions, which device wrote it, when it last helped, and why it was recalled.
- New capture paths (collectors, importer, on-demand extraction) land quarantined or labelled; nothing silent enters the approved set.
- Team memory reuses the blind envelope; the server never holds a team key or plaintext.
- Linux passes the same memory + egress gates as macOS; operators can see last pull, applied, rejected, parked, and marker age.

## Key Decisions

1. **Sequence Slice 0 → A → E-platform → B → C → D.** Slice 0 lands blind-sync PR2 (Tasks 4–6), which the audit proved is still open. Sync correctness (A) follows because B–D read state A defines; the Linux egress break (E18) rides with A since a broken egress gate invalidates every blindness claim on that platform. Team/org (D) goes last — it is the only phase needing new key-distribution design.
2. **Fix the `body_hash` inconsistency before building the chain (A0).** One canonical `canonical_body_hash()` helper used by write, read, and admin paths, plus a one-time recompute of divergent rows. `previousBodyHash` is then defined as the predecessor's `body_hash` — no second hash semantics to argue about.
3. **`previousBodyHash` goes inside the sealed payload, not the plaintext fields.** Zero `firestore.rules` change (blob is opaque; sealed `schemaVersion >= 2` already required). Chain rule, stated completely: a new reader applies an update only if its `previousBodyHash` matches the current body's hash (fast-forward), holds it in a bounded pending queue on mismatch, and after a gap timeout surfaces `UNRESOLVED_GAP` to doctor instead of stalling. **Forward-safety gate (precedes any new sealed field): every sealed reader (Swift, C#, any Rust consumer) must prove unknown-field tolerance by opening a v+1 fixture payload in-test; any strict reader is made tolerant first, or no new field ships. Hold-back queue is persisted alongside `sync_state` and re-evaluated each merge, so a restart cannot silence a gap. Fork rule:** two updates sharing one predecessor resolve by the existing LWW (`updated_at`, tie-break `memory_id`); the loser is auto-marked superseded-by the winner. Omitting `previousBodyHash` is legal only for genesis bodies; any update to a known memory without it is rejected, so the chain cannot be bypassed by omission.
4. **Forget is a tombstone, not a delete — and retire reuses existing fields.** No new `kind` (the rules allowlist has none to give without a contract change). Forgetting writes an engine `forget_receipts(memory_id, forgotten_at, device)` row covering **the memory_id, not one hash** — every historic and future body under that id, including foreign-id replays, loses to the receipt. The retired sealed record reuses the row's existing kind with `valid_to` set; the uploader **synthesizes it from the receipt** (a deleted row cannot upload itself), and the pull path applies an incoming retired record as a local forget + receipt. Receipt check precedes chain check, so a retire wins regardless of arrival order. Re-remember escape rule: a fresh write mints a new `memory_id`, so deliberate re-learning after forget is unaffected; if old retired and new active records share a convergence key, LWW favors the newer active record.
5. **Doctor stays report-first.** The sync-ledger pass (watermark sanity, orphan `agent_memory_bodies`, parked supersedes, receipt coverage, `UNRESOLVED_GAP`) reports findings with codes; `--apply` prunes only orphans **older than a grace period and unreferenced by any un-uploaded row or receipt**, and parked supersedes only after N days. Same shape as today's aux-scan cursor walk.
6. **Alias resolution rides the supersede mechanism, not a new synced table.** `memory_aliases(folded_id → canonical_id)` stays a **local** index populated two ways: local `fold` calls and incoming supersede merges (spec §5 already replicates `superseded_by` chains). No new synced structure; a folded-away id resolves anywhere the supersede chain has arrived, and locally everywhere.
7. **Non-git project identity: explicit mapping must itself travel.** Resolution order: explicit mapping → git root → hashed path flagged **`provisional`**. The mapping travels two ways: an adopt-in-folder dotfile option (any device opening the synced folder inherits the id) and a `project adopt <id>` command for folders that don't sync. Provisional projects trigger a doctor warning and never silently split-brain: recall across a provisional id shows its provenance. Both engine `resolve_project` and daemon `resolveProjectIdentity` implement the same order.
8. **No migration for `sync_state`.** The table does not exist yet, so A5 is folded into Task 5 as "choose final column names now" — zero migration, exercised by `test_store_migrations.py` like every other additive table.
9. **Visibility reuses computed data, adds no new ranking.** "Why this" surfaces the RRF components already computed (both rankers); the timeline reads `memory_history`; the health card aggregates doctor + analytics counters. No new scoring, no new telemetry schema. Device attribution: `writer_device` travels **inside the sealed payload** (encrypted, never a plaintext field) and the pull path stamps it into local history `meta_json`; local writes stamp the local device id (daemon-supplied preferred, settled at implementation).
10. **Capture stays quarantined-by-default.** Importer rows and auto-collected rows enter as `quarantine`; on-demand Pro-model extraction reuses the #2501 model policy (member's own quota/keys, BurnBar blind) and stamps provenance `extracted_by` visibly. Importer runs in bounded batches with a cap + summary and a strict export-schema version gate.
11. **Team memory = same envelope, new key, new collection, team-bound AAD.** `team_memory_facts/{teamId}/facts/{docID}` sealed under a team vault key distributed via the per-device escrow-join pattern extended to a roster; doc-id derivation and AAD bind `teamId` (no cross-team aliasing even though paths already differ); per-member consent ANDed client-side (named v1 trust assumption: a compromised member client is out of scope as with all client-side gates); leave-team = key rotation with documented no-retroactive-plaintext semantics. Needs a short design spec before code (only item in the plan that does).
12. **Org ceiling degrades, member memory never bricks.** Cached Remote Config ceiling with a max-age; offline uses cache; past max-age the client denies only org-gated kinds and leaves member-local memory untouched. Fail-closed where it matters, fail-soft where it must.

## Risks / Rollback

- Sealed `schemaVersion` bump: forward-safe only after the §3 tolerance gate passes on every reader (rules already admit `>= 2`, so no contract change); rollback is a plain revert, receipts/alias tables additive-only.
- A0 recompute touches existing rows: run it as a data migration with a pre-backup (per `OpenBurnBarDatabase+MigrationBackup` precedent) and a dry-run count first; abort on any hash collision across distinct bodies.
- Team key distribution (D16) can fail closed into "no team sync" without affecting member sync — behind its own entitlement + toggle so a design miss cannot strand member data.
- Linux egress (E18) starts with reproduce-on-main; time-box to the break-on-main fix, file the rest as follow-ups rather than ballooning Slice 2.
- Copy-gate (E20) depends on locating the existing pattern; fallback is docs + manual reviewer, stated above.
