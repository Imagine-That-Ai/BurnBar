## 01-crypto-relay
Primitives are standard Apple CryptoKit, no homegrown AEAD/curve. Payload AEAD = AES-256-GCM (sealToBase64/openBase64, HermesRelayCrypto.swift:306-330), 32-byte keys from SecRandomCopyBytes with errSecSuccess check (:138-147). v3 key wrap = RFC 9180 HPKE Auth mode, suite P256_SHA256_AES_GCM_256, sender-authenticated by static relay key (sealKeyV3 :493-514, openKeyV3 :524-557); info='OpenBurnBar-HermesRelay-HPKE-v3|'+key_aad. v2 (legacy, gateway lane only) = bespoke HPKE-AuthEncap-shaped 2-DH, ikm=ECDH(eph,R)||ECDH(skS,R), HKDF-SHA256, info binds prefix||aad||enc||pkR||pkS (authenticatedWrappingKey :439-461). GCM nonces are CryptoKit-internal random per seal (no static IV). Empty HKDF salt is acceptable: fresh DH IKM + domain-separated info. No AES-CBC, no encrypt-without-MAC, no hardcoded keys, no disabled TLS verify, no weak RNG, no catch-and-continue (openKeyV3 normalizes-and-rethrows :548-556). Forward secrecy exists for the ephemeral DH leg ONLY; static-leg PFS and KCI resistance are explicit, correctly self-documented non-goals (:10-19). RED-FLAG scan of the two target files: clean. Caveats live in lane wiring, not the primitives.

## 02-cloudvault-signal
AEAD = AES-256-GCM everywhere (CryptoKit / AES/GCM/NoPadding), 12B random nonce, 128b tag, keys from SecRandomCopyBytes/SecureRandom; fresh nonce per seal (no reuse risk). Recipient seal = libsignal PublicKey.seal/PrivateKey.open (Curve25519 sealed-sender / HPKE-style) with info+associatedData both derived from canonical binding (strong domain separation, relocation-bound). Sender-auth = libsignal XEd25519 signature over a length-prefixed, NFC-normalized, byte-canonical message (domain + HPKE info + ciphertext + sorted wraps) verified vs PINNED key; byte-parity with Kotlin asserted by shared fixtures. Vault-key wrap = P256 ECDH + HKDF-SHA256 (OpenBurnBar-Escrow-v1, empty salt) -> AES-GCM. Recovery-key wrap = HKDF-SHA256 with FIXED salt recoverySalt (acceptable given 35-byte base32 high-entropy code). Recovery bundle = PBKDF2-HMAC-SHA256 100k iters (below OWASP-2023 600k). HKDF/HMAC search subkeys use empty salt + distinct info (deterministic by design for dedup/trapdoors; not a vault-key confidentiality boundary). vaultKeyID is truncated SHA256 (identifier, not a security boundary).

## 03-pairing-trust-revocation
Trust-chain signature is libsignal XEd25519 (XEdDSA over Curve25519): server reconstructs Montgomery-u -> compressed Edwards using the sign bit borrowed from signature[63], rejects non-canonical scalars (computerUseSecurity.ts:616-650 verifyXEdDSACurve25519Signature; malleability guard :627-628), then verifies standard Ed25519 over a reconstructed SPKI. Canonical signing bytes are domain-prefixed ('OpenBurnBar-CloudVault-DeviceTrust-v1') length-prefixed UTF-8 segments (:663-699) matching the Swift signer CloudVaultDeviceTrustChain.swift; approver public key is sourced ONLY from the published Firestore identity doc so an attacker cannot supply a matching key/sig pair. Fingerprints = base64(SHA256(keyBytes)); both server (:287) and client (CloudVaultTrustedDeviceChainVerifier.swift:109,137) re-bind the signed fingerprint STRING to actual key BYTES, so a backend key-swap-under-a-signed-fingerprint fails closed. Vault wrappers are ECIES-P256-AESGCM; rotation enforces generation == current+1 and revokes all old-vaultKeyID wrappers (cloudVaultRotation.ts:185,299-307). High-risk nonce is single-use, txn-consumed, short-TTL (appCheckAttestation.ts:179-206).

## 04-transport-iroh
iroh provides QUIC/TLS1.3 with NodeId = Ed25519 public key; the QUIC handshake authenticates the remote NodeId (conn.remote_id()). Default relay is n0 public relay set (lib.rs:286,302 RelayMode::Default/presets::N0), optional pinned custom relay (:296); the relay is a NAT-traversal packet mux, never a TLS terminator, so no plaintext at the relay. Pairing uses Ed25519 (Curve25519.Signing) over a canonical pipe-delimited string openburnbar.iroh.pairing.v1|uid|connectionId|nodeId|relayURL|directAddresses|publishedAtMillis (IrohRelayPairing.swift:95-98) with sound canonicalization (sorted/deduped addrs, version prefix), but the verifying public key is cloud-distributed with no TOFU pin. Payload confidentiality/integrity is a SEPARATE layer (HermesRelayCrypto/Signal) applied by IrohRelayRequestHandler (open at :303, seal at :959) and survives a transport-level MITM. Transport tamper/reorder/drop within a connection is covered by QUIC ordering+AEAD+anti-replay; cross-connection replay of whole sealed envelopes is an app-layer AAD/nonce concern out of transport scope. Wire frame: 4-byte big-endian u32 length prefix + JSON, 512 KiB hard cap both directions. Dependency: iroh/iroh-services =1.0.0-rc.0 (pre-GA release candidate).

## 05-gateway-pop
PoP = Ed25519 over UTF-8 LF-joined, version-domain-separated payload ("OpenBurnBar.HermesGatewayPoP.v1/v2"): tokenHash|METHOD|path|bodyHash|nonce|timestamp (+canonical query in v2). Raw 32B key wrapped in fixed SPKI DER prefix for node createPublicKey; verify via crypto.verify(null,...) (callables/hermesGateway.ts:755). bodyHash compared constant-time via safeEqualHex/timingSafeEqual (hermesGateway.ts:513). Bearer token stored as sha256 only (no HMAC/pepper) — acceptable since token is high-entropy random AND PoP-gated; index is hash-keyed so no plaintext token at rest. Replay: per-(uid,clientId) nonce single-use via Firestore create-if-absent transaction; 5-min skew window == nonce TTL so no reuse gap. Approval decisions bound by device Signal-identity signature over {uid,deviceId,actionKind,subjectId,approve,nonce,issuedAt,identity} (computerUseSecurity.ts:840). Signal v4 PRODUCTION write set is empty (hermesGateway.ts:152); relay write versions v2/v3 only. gatewayPlaintextWriteAllowed() hard-returns false (hermesGateway.ts:189).

## 06-cloud-authz
Rules validate envelope STRUCTURE only, never that ciphertext decrypts or that the correct key was used. Sealed text pinned to AES-256-GCM + required AAD at schemaVersion>=2 (firestore.rules:462-500). Vault key wrappers pinned to ECIES-P256-AESGCM, base64 charset, 8 KiB cap (:2244-2247). Vault key continuity is rule-enforced: new cloud_vault_state/current write must match existing vaultKeyID (:2204-2205) and wrappers must matchesCurrentVaultKey (:2231), preventing a client from unilaterally rotating the active key via rules alone. Two legacy authz findings (RR-12 owner-delete of key wrappers; T-CL-6/RR-6 unconstrained users/{uid} root doc) are REMEDIATED in current code and covered by rr12-relay-and-root.test.js.

## 07-daemon-privsocket
HPKE = Curve25519 + HKDF-SHA256 + ChaCha20-Poly1305 (RemoteUnlockCredentialEnvelopeCrypto.swift:70). 32B encapsulated key prepended to AEAD ciphertext; context binding via length-prefixed HPKE info (requestId/sessionId/clientIntentId/credentialKind/recipientKeyId), re-derived and compared by recipient before open(:95-106) — sound. AEAD AAD intentionally empty for Android Tink interop (acceptable; info is in the key schedule). DR = anchor apple generic and certificate leaf[subject.OU]=\"4Y367DF25B\" and exact-identifier OR list (PrivilegedSocketTrust.swift:69); hardened-runtime (0x10000) + library-validation (0x2000) enforced programmatically via SecCodeCopySigningInformation, not in the DR string (M-9 — CSRL cannot express CD flags). LOCAL_PEERTOKEN pinned to 0x006 with a live-socket regression test (prior 0x102 typo silently fail-closed). Local-auth proof: Ed25519 over proofId|deviceId|signedIntentHash|authenticatedAt|expiresAt where signedIntentHash == canonicalAgentGrantRequestHashHex (op-hash binding); single-use via in-mem set + persisted consumedProofStore; TTL-bounded. SE-signed grants skip explicit proof (biometric SE signature is itself user-presence). All proof validation lives in the app, not the daemon.

## 08-agent-runtime-tools
Remote grant requests are Ed25519-signed (default; key-kind selectable) envelopes verified against a pinned controller key with counter+timestamp replay protection via PhoneControlAuthorityValidator (AgentCapabilityGrantQueueListener.swift:84-88). A separate signed localAuthProof is required for privileged/YOLO grant admission (AgentCapabilityGrantStore.swift:85-94). Local Mac grants are gated by LAContext deviceOwnerAuthentication, fail-closed (DesktopGrantLocalAuthenticator.swift:31 throws on unavailable/failed). YOLO unrestricted-shell audit digest is a one-way SHA-256 of the command (privacy-preserving, non-reversible) — attribution only. Trust anchor for remote grants is the controller pin; if first-pin TOFU reads a cloud Firestore doc, integrity depends on firestore.rules write protection (cross-domain, UNKNOWN here).

## 09-agentic-prompt-memory
Out of domain. encryptedSearch.ts keeps plaintext slug/name unprojected (:499,:552) and performs no LLM/model-provider call, so it presents no prompt/RAG exposure surface. wrapUntrusted's delimiter-breakout defense (U+2011 sentinel swap + provenance attribute sanitization) is a string-hardening control, not cryptographic; it is sound against literal-boundary forgery but does not constrain semantic injection inside the block (mitigated only by the model-side CRITICAL RULE instruction).

## 11-android-masvs
Vault content: AES-256-GCM, 12-byte SecureRandom nonce, 128-bit tag, AAD=path binding (uid/collection/docId/field); blob integrity migrated SHA-256->keyed HMAC (CloudVaultCrypto.kt:316-326); schema-versioned v1 legacy/v2 current. Signal at-rest: per-message random 32-byte content key, AES-256-GCM with canonical-AAD binding; content key HPKE-sealed per recipient; ECDSA-P256 sender signature over length-prefixed, NFC-normalized, byte-sorted domain-separated message (Swift byte-parity). Remote Unlock: HPKE DHKEM-X25519-HKDF-SHA256 + ChaCha20-Poly1305 NO_PREFIX, structured length-prefixed info as AAD, E2E to Mac recipient key (RemoteUnlockCredentialEnvelopeCrypto.kt:50-95). Note: sealText@246 uses 'Cipher.DECRYPT_MODE.let { Cipher.ENCRYPT_MODE }' — functionally ENCRYPT (constant-folds), not a bug but an audit/readability smell. AndroidLocalSecretBox key uses AES/GCM with BLOCK_MODE_GCM, PADDING_NONE, randomized encryption required (CloudVaultCrypto.kt:1210-1218) but no setKeySize, no StrongBox, no setUserAuthenticationRequired.

## 12-attachments
Gateway sealed attachments: agent-side AEAD (relay/ratchet/signal envelope) seals plaintext bytes; server stores opaque octet-stream and gates integrity on recomputed SHA-256 of the CIPHERTEXT (hermesGateway.ts:1582). byteCount is ciphertext length (~plaintext+28B GCM overhead). Server holds no content key — keys are agent/device held (E2EE plausible if envelope keys device-held; verify in crypto domain). Mercury at-rest seal: AES-256-GCM (MediaFrameAEAD/OBMFA1), AAD bound to manifestId(FNV-1a gopID)+blobHash; key = per-media-session key, rotates with session; atomic temp+replace prevents truncated plaintext. Mercury wire integrity: BLAKE3 content-addressing via iroh export verifies hash so byte substitution infeasible — but manifest metadata (filename/mime/size) is NOT covered by any signature/MAC.
