# Trust Boundaries

Each boundary is evaluated as implemented in repository evidence. "Missing controls" are not accusations of exploitation; they are controls not proven by the codebase.

| Boundary | Crosses | Assumed trust | Auth/Authz | Encryption/integrity/replay | Logging | Compromise result | Existing controls | Missing controls | Residual risk |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| User device <-> BurnBar Cloud | Auth tokens, sealed envelopes, metadata, provider requests | Cloud trusted for authz/metadata, not sealed plaintext | Firebase Auth/App Check; Gateway bearer+PoP; scopes | TLS; AES-GCM/HPKE AAD for sealed paths; PoP nonce replay cache | Cloud logs/Sentry scrubbers | Cloud can observe metadata, drop/reorder, target users | Auth/App Check fail closed; sealed-only current Gateway writes | Live deployed config proof; complete endpoint matrix | Metadata and availability remain exposed |
| Mobile app <-> OS keychain/keystore | Private keys, tokens | OS trusted if device uncompromised/unlocked | App process identity | Platform storage; Android wraps with Keystore | Native crash uncertain | Malware/unlocked theft can extract or use secrets | Keychain/Keystore use | Hardware/user-presence not proven | Endpoint compromise out of scope |
| Desktop app <-> OS keychain | Provider keys, CloudVault/Signal/relay keys | OS user session trusted | App process | Keychain accessibility | OSLog private markers | Malware can use keys after unlock | Keychain, redactors | Secure Enclave/biometric not proven | Endpoint plaintext exposure |
| Desktop app <-> local daemon | RPC, runs, approvals | First-party signed local clients trusted | Peer code-signature auth in production; controller checks | Unix socket permissions; max request bytes | Daemon logs/audit | Rogue local process may try RPC abuse | 0700 dir/0600 socket, fail-closed peer auth | Unsigned/test mode risk; live signing proof | Local privilege boundary is not OS sandbox |
| Local agent <-> filesystem | Files, patches, attachments | Workspace policy trusted; files untrusted | Tool policy/grants/user approval | OS permissions; no crypto boundary | Tool/audit logs | Data exfiltration or mutation | approval for applyPatch, grant model | Strong workspace sandbox not proven | Approved or compromised agent can read/write |
| Local agent <-> shell/process | Commands/env/stdout | Shell is dangerous | Approval/grants; CLI allowlists | Process args/env; no shell in some paths | redacted launch errors/audit | RCE under user account | env/arg allowlists, approval | YOLO/unrestricted shell risk; Forge prompt-only limits | High residual risk by design |
| Local agent <-> network | Provider calls, web fetches, MCP | Network outputs untrusted | Provider tokens/scopes | TLS where provider uses it | Provider/audit logs | Exfiltration/provider disclosure | route selection, privacy mode | Egress firewall not proven | Model/provider sees routed data |
| Cloud service <-> Firestore | Admin SDK reads/writes | Functions trusted | Code-enforced owner checks; rules for client SDK | GCP internal/TLS | Cloud logs | Admin SDK bypass can expose data if code/IAM abused | rule tests, assertOwnership | Full callable matrix/live IAM | Insider/cloud compromise metadata exposure |
| Cloud service <-> Storage | Ciphertexts, avatars, signed URLs | Storage trusted for object auth | Signed URLs/Storage rules | TLS; client-side encryption for sealed blobs | GCP logs | Mis-scoped URL/rule leaks blobs | short upload URLs, finalize checks | Gateway download path inconsistent | Ciphertext plus metadata exposure |
| Cloud service <-> queue/pubsub | Jobs/events if any | Unknown | Unknown | Unknown | Unknown | Unknown | Not identified as major path | Inventory live infra | Unknown |
| Cloud service <-> push provider | Push tokens/payloads | Provider trusted for delivery | Platform credentials | Provider TLS | Provider logs | Metadata leak/spam notifications | generic previews where used | Full payload inventory | Push provider sees metadata |
| Cloud service <-> model provider | Prompts/digests/attachments | Provider untrusted processor | API keys | TLS; provider policy | usage/audit | Provider sees routed data and can return malicious content | prompt wrapping, JSON output filtering, privacy mode | DLP/secret filters not complete proof; retention config unknown | Confidentiality and output-integrity risk |
| Cloud service <-> analytics/crash | Errors/events | Provider trusted processor | DSN/API credentials | TLS | Sentry/Crashlytics | Sensitive data in crash events | Sentry beforeSend scrub | Native/mobile crash proof missing | Residual privacy risk |
| Device <-> device through relay | Sealed messages and metadata | Endpoints trusted; relay metadata-trusted | bearer+PoP/pinned keys | envelope AAD, sender verification | Gateway/audit logs | Relay cannot decrypt current content but can DoS/metadata | HPKE/AES-GCM, create-if-absent | Full FS/PCR not proven | Metadata, replay gaps, endpoint compromise |
| Web client <-> browser storage | Web state if present | Browser same-origin trusted | Web auth/session | TLS; browser storage | Browser/devtools | XSS/session theft | Not fully inventoried | Web client security review | Unknown |
| Admin interface <-> production | IAM, data, secrets | Admins highly trusted | GCP/GitHub/Firebase IAM | Console/audit logs | Cloud/GitHub audit | Insider can access metadata/secrets depending IAM | docs/workflows | Live IAM/access reviews | High until proven |
| CI/CD <-> production deploy | Artifacts, secrets, deploy credentials | CI trusted | GitHub envs/OIDC/secrets | GitHub/GCP TLS/signatures | workflow logs | Malicious artifact/deploy | release gates, tests, signing | tag-pinned actions, live branch protection proof | Supply-chain risk |
| Build system <-> artifact registry | SBOM, binaries, signatures | Build trusted | GitHub/GPG/cosign | signatures/checksums | release logs | Tampered artifacts | notarization/Sparkle/cosign | Full SLSA coverage/repro builds not proven | Artifact provenance partial |
| Human user <-> AI agent | Goals, approvals, explanations | Human approvals trusted but phishable | UI identity/session | N/A | audit/history | Social engineering approval | approval prompts, risk labels | UX anti-phishing/safety-code proof | Human-agent trust exploitation |
| AI agent <-> tools | Tool calls/results | Agent output untrusted | Deterministic policy | schemas/approval state | audit logs | Tool misuse/RCE/data leak | allowlists, approval | Strong sandbox/egress controls incomplete | High residual agentic risk |
| AI agent <-> memory | Memory writes/reads | Memory partially trusted | owner/scopes/local trust | sealing/cloaking where implemented | memory/audit logs | Persistent prompt/context poisoning | redaction/confidence filters | deterministic provenance/quarantine/delete | Persistent manipulation risk |
| AI agent <-> retrieved content | Docs/web/emails/logs | Retrieved content untrusted | tool/data-source auth | prompt wrappers only | context logs maybe | Indirect prompt injection | `<UNTRUSTED_CONTENT>` wrappers | hard context separation not proven | Model may follow malicious data |
| AI agent <-> other agents | Inter-agent/tool outputs | Other agents untrusted unless scoped | MCP scopes/local grants | protocol-level only | MCP/audit | Cascading failures | scopes/rate limits | strong agent identity model incomplete | Rogue/cascading risk |
