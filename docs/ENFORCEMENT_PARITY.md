# Enforcement Parity — which gate binds which stack

> **Source of truth for Operation 9 P-CQ-5.** Documents the actual binding gates
> across every platform stack in the BurnBar monorepo. Each row is evidence-backed:
> the gate name, the workflow file, and the check that enforces it.

## The Swift-first reality

The repo's enforcement tooling grew up around the Swift/macOS app first. SwiftLint,
`swift test`, `xcodebuild`, and the CodeQL Swift analysis all bind the Apple stack.
The duplication gate (jscpd) and the detekt complexity gate were similarly Swift/Kotlin/TS-first:
jscpd scanned only `swift`, `kotlin`, `typescript`, `tsx`, `javascript`, `jsx`, and detekt
blanket-exempted `**/ui/**` (367 Kotlin files — the largest code mass in the Android tree).

This document records the **current** binding so a re-auditor can verify parity, and
tracks the gaps closed by Operation 9.

## Duplication gate (jscpd) — format coverage

| Format | In `.jscpd.json` `format` array? | Verified in `verify-jscpd-report.mjs` `requiredFormats`? |
|--------|----------------------------------|--------------------------------------------------------|
| swift | yes | yes |
| kotlin | yes | yes |
| typescript | yes | yes |
| tsx | yes | no (counts toward total, not required individually) |
| javascript | yes | no |
| jsx | yes | no |
| **csharp** | **yes** (added P-CQ-5) | **yes** (added P-CQ-5) |
| **rust** | **yes** (added P-CQ-5) | **yes** (added P-CQ-5) |

**Gate:** `.jscpd.json` → `code-quality.yml` job `duplicate-code` →
`scripts/ci/verify-jscpd-report.mjs` (rejects vacuous reports that omit a required format).

**What P-CQ-5 changed:** added `csharp` and `rust` to both the jscpd `format` array and
the verifier's `requiredFormats`. A report that omits either format now fails the
`Reject vacuous duplicate-code reports` step. The verifier self-test
(`scripts/ci/verify-jscpd-report.test.mjs`) includes regression cases for both.

**Why jscpd supports both natively:** jscpd uses tree-sitter grammars; `rust` and
`csharp` are built-in format names (verified: `npx jscpd@4 --format rust …` produces a
valid report with `statistics.formats.rust.total.sources`).

## Branch-protection binding

All gates listed above are **required** status checks per
`governance/branch-protection.main.json` `required_status_checks.contexts`. The
`Rust (fmt + clippy + cargo-deny)` context binds all Rust crates. The Android gate
(`droid-review`) and `Android ktlint` contexts bind the Kotlin stack. The Windows
gates (`PR Windows Gate`, `PR Windows Full Gate`) bind the C# stack.

The jscpd duplication gate runs in `code-quality.yml` → `Duplicate Code Detection (jscpd)`,
which is NOT in the required contexts list (it runs as a scheduled + PR-triggered
advisory lane). The `verify-jscpd-report.mjs` check that enforces format coverage runs
inside that same job. The format parity this PR adds means a future jscpd run that
silently drops C# or Rust from its report would fail the vacuous-report gate.

## Gaps still open (tracked separately)

- **C# lint gate:** no dedicated C# analyzer lane beyond `TreatWarningsAsErrors` (P-CQ-4
  lands `Directory.Build.props`). A Roslyn analyzer lane is a future enhancement.
- **Python duplication:** jscpd does not scan Python (`functions/scripts/**` is in the
  jscpd ignore list). Python is linted by ruff; duplication detection is not a tracked gap.
- **Remaining false `generated-by` headers:** `SwarmTextCoordinates.kt`,
  `AuroraNavGlyphs.kt`, and `AuroraTheme.kt` also carry `generated-by` headers for
  scripts that don't exist. They are out of scope for this packet but noted here for
  a follow-up cleanup.
