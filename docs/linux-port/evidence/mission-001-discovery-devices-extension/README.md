## Firmware Lane Attempt / Blocker Artifact

Product firmware lane probes:

```text
busctl introspect org.freedesktop.NetworkManager /org/freedesktop/NetworkManager
udevadm info --export-db
```

If prerequisites are present, the lane constructs:

```text
busctl introspect org.freedesktop.NetworkManager /org/freedesktop/NetworkManager
udevadm info --query=property --name=/dev/ttyUSB0
python3 -m esptool --chip esp32 --port /dev/ttyUSB0 write_flash 0x0 /opt/openburnbar/pixelclock.bin
```

Real container blocker check:

```text
docker run --rm openburnbar-linux-toolchain:mission-001 bash -lc 'set -u; printf "avahi-browse="; command -v avahi-browse || true; printf "avahi-publish-service="; command -v avahi-publish-service || true; printf "busctl="; command -v busctl || true; printf "udevadm="; command -v udevadm || true; printf "system-bus="; if test -S /run/dbus/system_bus_socket; then echo present; else echo missing; fi; printf "serial-devices="; ls -1 /dev/ttyUSB* /dev/ttyACM* 2>/dev/null || echo none'
```

Observed output:

```text
avahi-browse=avahi-publish-service=busctl=udevadm=system-bus=missing
serial-devices=none
```

Blocker: the available Linux container has no Avahi CLI, no NetworkManager system bus, no `busctl`, no `udevadm`, and no PixelClock serial device. Firmware flashing remains an implemented attempted lane, not a non-goal.
