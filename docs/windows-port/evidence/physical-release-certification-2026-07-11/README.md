# Windows physical release-certification evidence

This namespace is the independent certification lane for the Windows release gates named by the 2026-07-11 certification assignment. It is an addendum to [`WINDOWS_MACOS_PARITY_INDEPENDENT_AUDIT_2026-07-09.md`](../../WINDOWS_MACOS_PARITY_INDEPENDENT_AUDIT_2026-07-09.md), not a replacement for that audit or for PR #1542's separate evidence worktree.

## Evidence policy

- Every receipt uses `openburnbar.windows.release-certification-receipt.v1`.
- Every receipt records source commit, dirty-tree state, artifact identity, architecture, workflow run fields, signature result, device, protocol, timestamps, exit code, and hashed evidence files.
- `PASS` is reserved for the surface actually exercised. A source test, hosted runner, Windows VM, package registration, or unit test never becomes a physical-device PASS.
- No real credential, token, private key, or secret value is stored in this bundle. Command output is redacted before it is written.
- `SHA256SUMS` is generated by `scripts/windows-port/validate-release-certification-evidence.mjs` and validated before an attempt is accepted.

The exact external blockers are recorded in `blockers/*.md`. The signed MSIX/resource lifecycle work in PR #1541 and the consolidated evidence in PR #1542 remain separate lanes and are not overwritten here.

## Harness entry points

```text
node scripts/windows-port/run-local-certification-checks.mjs <bundle-directory>
pwsh scripts/windows-port/run-physical-release-certification.ps1 `
  -RepoRoot C:\src\BurnBar `
  -OutputDir C:\src\BurnBar\docs\windows-port\evidence\physical-release-certification-2026-07-11\physical-x64 `
  -Platform x64 `
  -ArtifactManifestPath C:\evidence\signed-artifact.json `
  -HardwareAttestationPath C:\evidence\hardware-attestation.json `
  -PhysicalHardware
node scripts/windows-port/validate-release-certification-evidence.mjs <bundle-directory>
```

The PowerShell runner requires an explicit hardware attestation and rejects virtualized host fingerprints, missing signed artifact identity, and incomplete supplemental receipts. It invokes the existing Windows UIA profile but keeps the manual Narrator/keyboard protocol as a separate required receipt.
