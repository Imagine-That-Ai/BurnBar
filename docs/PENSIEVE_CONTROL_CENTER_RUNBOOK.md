## ⚠️ Corrections to the canonical doc (read before touching Xcode)

The architecture doc (`PENSIEVE_CONTROL_CENTER.md` §"Native build-wiring") says to
add files **in Xcode** and warns against "blind pbxproj rewrites." That warning is
right that you must **never hand-edit `OpenBurnBar.xcodeproj/project.pbxproj`** —
but the *reason* and the *fix* are different from what that doc implies:

- **The project is generated by XcodeGen.** `project.yml` is the source of truth;
  `project.pbxproj` is **regenerated** by `xcodegen generate --spec project.yml`
  (xcodegen 2.45.3 is installed). Dragging files into Xcode is pointless — the next
  `xcodegen generate` wipes manual project edits.
- **Most new files need no project edit at all.** Targets glob whole directories
  (`AgentLens`, `OpenBurnBarMobile`, `OpenBurnBarDaemon/Sources/...`), so every new
  file under those dirs auto-compiles after `xcodegen generate`.
- **Only TWO files need a `project.yml` edit** because they live *outside* the
  globbed dirs: `packages/data-domains/gen/DataDomains.swift` and
  `packages/design-tokens/dist/swift/PensieveTokens.swift`. See Stream A, step A2.

So the real Apple flow is: **edit source for registration → edit `project.yml` for
the 2 package files → `xcodegen generate` → `xcodebuild`.** No Xcode GUI required.

### E1. Native recovery-key crypto + re-entry UI
**Why it's needed:** current clients send a **plaintext** key
(`DataVaultStore.swift:349-356` sends `["recoveryKey": key]`) which **fails**
server validation. The server requires an envelope:
`{ algorithm:"AES-256-GCM", wrappedVaultKey:<=8192 base64, verificationHash:<lowercase
SHA-256 hex>, keyVersion:1..100 }`. **Recovery uses a SYMMETRIC wrap** (derive a
wrapping key *from* the recovery key), **not** the ECDH escrow path, and
`verificationHash = SHA-256(derived wrapping key bytes)`.

1. Add to `OpenBurnBarCore/.../SharedModels/CloudVaultCrypto.swift`:
   - `generateRecoveryKey()` → high-entropy human-shown string (e.g. Crockford
     base32, ~168 bits from `SecRandomCopyBytes`).
   - `deriveRecoveryWrappingKey(from:)` → `SymmetricKey` via HKDF-SHA256 (salt
     `OpenBurnBar-Recovery-Salt-v1`, info `OpenBurnBar-Recovery-Wrap-v1`, 32 bytes).
   - `wrapVaultKeyWithRecovery(vaultKey:recoveryKey:)` → `(wrappedVaultKeyBase64,
     verificationHash)` where wrap = `AES.GCM.seal(...).combined.base64` and
     `verificationHash = sha256Hex(Data(wrappingKey))`.
