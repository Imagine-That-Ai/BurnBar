## Key Decisions

- **Eight streams, not fewer**: the score needs +18 category-points and the surfaces are disjoint, so parallelism is free. Collapsing streams would serialize unrelated files for no safety gain.
- **One owner per file**: Stream A owns `.github/workflows/deploy-production.yml` exclusively; Stream F's `break_glass` hardening is implemented as a review suggestion to A (or lands after A merges) to avoid a same-file collision. Stream E owns `firestore.rules`. Stream D owns `health.ts`/`sentry.ts`/`logging.ts`. All other streams are read-only outside their surfaces.
- **Evidence counts as points**: Series A readiness (+3 target) moves on receipts, not just code — hence a dedicated evidence-packet stream (G) rather than treating docs as each stream's afterthought.
- **Fix-or-gate for perf**: Stream C may ship a feature gate + load evidence instead of a full data-plane rewrite. An unbounded OOM vector gated with a tested limit is tonight-done; a half-finished pagination is not.
- **Auto-rollback with a manual-drill fallback**: if automating rollback-in-workflow proves risky tonight, Stream A ships a drilled, timed, receipted manual rollback plus staffed-window procedure. Either closes the blocker; automation is preferred, drill is acceptable.
