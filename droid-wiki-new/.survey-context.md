# Survey Context — OpenBurnBar

## Repo summary
OpenBurnBar is a native macOS menu bar app that tracks token usage and cost across AI coding agents (Claude Code, Factory Droid, Codex, Kimi, etc.) in real time. It is daemon-first and local-first: local SQLite (GRDB) plus a JSON-RPC daemon (`OpenBurnBarDaemon`) are canonical. Firestore and iCloud are optional replication planes. The project also ships iOS/Android companion apps, a VS Code/Cursor extension, and Firebase Cloud Functions.

## Tech stack
- macOS app: SwiftUI + GRDB + XcodeGen (`project.yml`)
- iOS companion: SwiftUI + GRDB + shared core
- Android companion: Kotlin + Jetpack Compose + Firebase
- Daemon + CLI: Swift Package (`OpenBurnBarDaemon/`)
- Shared contracts: `OpenBurnBarCore/` Swift package
- Extension: TypeScript (`extensions/openburnbar/`)
- Cloud functions: TypeScript (`functions/src/`), 49 callables
- iroh transport: Rust (`crates/openburnbar-iroh/`) compiled to XCFramework + AAR via UniFFI

## Major subsystems
- AgentLens (macOS app UI, parsers, GRDB, dashboard, settings, Hermes chat, Computer Use)
- OpenBurnBarDaemon (JSON-RPC server, mission control, provider routing, HTTP gateway, connector plane)
- OpenBurnBarCore (shared types, RPC contracts)
- OpenBurnBarMobile (iOS companion: Agent Watch, Mercury, Insights)
- android/ (Android companion with iOS parity)
- extensions/openburnbar/ (VS Code/Cursor extension)
- functions/ (Firebase Cloud Functions)
- crates/openburnbar-iroh/ (Rust P2P transport)

## Key data flows
1. Log ingestion: parsers read agent session files → local SQLite
2. Aggregation: UsageAggregator coordinates parsers → GRDB
3. Retrieval: projection pipeline builds FTS + embeddings from SQLite
4. Consumption: dashboard / Hermes / Insights read from SQLite
5. Sync: CloudSyncService merges local vs Firestore with optimistic concurrency
6. Daemon RPC: app ↔ daemon for missions, quota, routing, connectors

## Key patterns
- Local-first: SQLite is canonical; Firestore/iCloud are optional replicas
- GRDB over Core Data for ergonomic Swift SQLite
- UniFFI for iroh: single Rust crate → XCFramework + AAR
- Daemon-first: macOS app is a UI shell over JSON-RPC daemon
- `@MainActor` for UI, structured concurrency elsewhere
- `*Service`, `*Store`, `*Actor`, `*Client` naming boundaries per ADR-001
- Circuit breakers in Functions via `resilienceHelpers.ts`
- `onCallProduction` for production callables (logging + Sentry)

## Glossary seeds
- AgentLens: the macOS app (historical name, product is OpenBurnBar)
- Daemon: `OpenBurnBarDaemon`, local JSON-RPC background service
- GRDB: Swift SQLite wrapper used for local persistence
- Hermes: chat backend (Local Index CLI bridge or Hermes webapi localhost:8642)
- Mercury: P2P media (file transfer, screen share, calls) over iroh
- iroh: Rust P2P transport library (UniFFI bindings)
- Computer Use: agent drives Mac; phone mirrors + controls
- Mission control: daemon-backed project registry, scheduling, dispatch
- Connector plane: GitHub/Slack/Linear/PostHog/Sentry/Gmail integrations
- Routing pools: local OpenAI-compatible gateway for Cursor/Droid/Forge/etc.
- Editorial Observatory: Insights redesign with eyebrow + headline + findings
